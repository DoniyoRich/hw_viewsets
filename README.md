## Описание

1. Создан Django-проект, подключен DRF в настройках.
2. Созданы следующие модели:

### Пользователь:

- все поля от обычного пользователя, но авторизацию заменена на email;
- телефон;
- город;
- аватарка.

### Курс:

- название;
- превью (картинка);
- описание.

### Урок:

- название,
- описание,
- превью (картинка),
- ссылка на видео.
  Урок и курс - это связанные между собой сущности.
  Уроки складываются в курс, в одном курсе может быть много уроков. Реализована связь "один-ко-многим".

3. Описаны CRUD операции для моделей курса и урока.

Для работы контроллеров описаны простейшие сериализаторы.
При реализации CRUD для курсов и уроков реализованы все необходимые операции
(получение списка, получение одной сущности, создание, изменение и удаление).
Для курсов использованы Viewsets, а для уроков - Generic-классы.

Для начального заполнения БД и тестирования данных подготовлена фикстура ***lms_fixture.json*** (в папке fixtures).


### ***Обн. 19.06.2025***

Для модели курса добавлено в сериализатор поле вывода количества уроков.
Поле реализовано с помощью SerializerMethodField().

Добавлена новая модель "Платежи" в приложение users со следующими полями:

- пользователь
- дата оплаты
- оплаченный курс
- оплаченный урок
- сумма оплаты
- способ оплаты: наличные или перевод на счет.

Поля ***пользователь***, ***оплаченный курс***, ***оплаченный урок*** имеют внешние ссылки на соответствующие модели.

В сериализаторе для модели курса реализовано поле вывода уроков. Вывод реализован с помощью сериализатора для связанной модели.
Один сериализатор выдает и количество уроков курса и информацию по всем урокам курса одновременно.

Настроена фильтрация для эндпоинта вывода списка платежей с возможностями:

- менять порядок сортировки по дате оплаты
- фильтровать по курсу или уроку
- фильтровать по способу оплаты.


### ***Обн. 22.06.2025***

Реализован CRUD для пользователей, в том числе регистрация пользователей, в проекте используется JWT-авторизация.
Эндпоинты для авторизации и регистрации остаются доступны для неавторизованных пользователей.

Заведена группа модераторов и описаны для нее права работы с любыми уроками и курсами, но без возможности их удалять и создавать новые.
Заложен функционал такой проверки в контроллеры.

Описаны права доступа для объектов таким образом, чтобы пользователи, которые не входят в группу модераторов,
могли видеть, редактировать и удалять только свои курсы и уроки.


### ***Обн. 29.06.2025***

Для сохранения уроков и курсов реализована дополнительная проверка на отсутствие в материалах ссылок на сторонние ресурсы, кроме youtube.com.
Ссылки на видео можно прикреплять в материалы, а ссылки на сторонние образовательные платформы или личные сайты — нельзя.
Для этого создан отдельный файл validators.py, в котором реализован валидатор, проверяющий ссылку, которую пользователь хочет записать в поле урока с помощью класса.
Валидатор интегрирован в сериализатор.


Добавлена модель подписки Subscription на обновления курса для пользователя.

Модель подписки содержит следующие поля:
 - пользователь (FK на модель пользователя)
 - курс (FK на модель курса).

Реализован эндпоинт для установки подписки пользователя и на удаление подписки у пользователя.

Реализована пагинация для вывода всех уроков и курсов.

Написаны тесты, которые проверяют корректность работы CRUD уроков и функционал работы подписки на обновления курса.

В тестах использован метод setUp для заполнения базы данных тестовыми данными.
Для аутентификации пользователей использован ***self.client.force_authenticate()***.

Результат проверки покрытия тестами сохранен в папке ***htmlcov***.
